什么是 DeepSeek Harness (DSH)

一句话概括

DeepSeek Harness (DSH) 是一个开源的 coding / 自动化 agent 框架，采用 一切皆插件 的架构：核心只留 AgentLoop 与抽象缝，具体能力全靠插件组合。

核心定位

特性DSH 定位
本质独立进程，有自己的配置(/.dsh/)、会话(/.dsh/sessions/)、权限与沙箱体系
交互方式非聊天框，也非 IDE 补全插件，而是可组合的能力平台
模型支持多 Provider、多模型路由（llm-pi-ai），可灵活切换模型
扩展方式写插件扩展能力，通过 patch 叠加配置而非修改核心
工作台支持 Web 工作台（dsh web）和 CLI 一次性任务（dsh –profile headless）

避免误区：DSH 不是固定功能的工具，而是一个可组合的框架。核心不包含具体能力，仅提供循环与抽象接口（ctx.llm、ctx.tools、ctx.sandbox 等），实际能力通过插件完全由社区和用户贡献。

DSH 是什么

1. 独立进程的 Agent

DSH 以独立进程运行，拥有独立的配置和会话管理：

  • 配置目录：~/.dsh/ - 存储用户配置、Profile、Bundle 等
  • 会话目录：~/.dsh/sessions/ - 每次会话的历史记录和状态
  • 权限与沙箱：内置权限预设和命令沙箱，确保操作的安全性

2. 非聊天框的能力平台

与其将 DSH 视为聊天机器人，不如将其视为一个可插拔能力的工作台：

  • 读写文件：tool-fs 插件处理文件系统操作
  • 执行命令：tool-bash 插件执行 shell 命令
  • 搜索历史：session_search 工具查询历史会话
  • 多模型路由：支持多 Provider 模型自由切换
  • 多 Agent 协作：可以将任务拆分给多个 Agent 并行执行

3. 插件化架构

“一切皆插件” 是 DSH 的核心设计哲学：

概念说明
SDK从另一进程驱动，基于 JSON-RPC wire protocol / client / server
Cordis底座框架，提供 Context/服务注入/插件装载的组合框架
Harness组合出来的完整 agent 应用：循环、工具、会话、沙箱
Profile插件的组合配置：bundle patch 层叠加用户覆盖层
Bundle自带 patch 的插件包，作为一层加入 profile
Seam能力缝——抽象能力接口（ctx.llm、ctx.tools、ctx.sandbox…），实现可换各能力包

DSH 核心概念

1. 主要概念解释

概念位置/说明
SDKpackages/sdk - 从另一进程驱动的核心库，实现 client / server 架构
Cordis@deepseek-ai/cordis - 底座框架，提供 Context/服务注入/插件装载功能
Harness完整的 agent 应用组合：包含循环机制、工具集、会话管理、沙箱环境
Profile$DSH_HOME/profiles/<name> - 插件的组合配置，支持层叠叠加
Bundle自带 patch 的插件包，作为基础层加入到 Profile 中
Seam抽象能力接口：ctx.llm、ctx.tools、ctx.sandbox 等，实现能力的可插拔

2. 三种启动方式

方式命令说明
Web 工作台npx @deepseek-ai/dsh web官方零安装入口，启动 Web UI（默认 127.0.0.1:3080）
一次性任务dsh --profile headless "跑一下测试"执行完即退出，不启动 Web 界面
显式 Profiledsh --profile web显式指定使用 web profile

说明：web 与 headless 是内置 Profile 模板。--profile headless <task> 是一次性任务入口（dsh run 已移除）。

3. 核心能力速览

DSH 可以进行以下类型的操作：

场景如何实现
改代码 / 读文件tool-fs / 文件系统插件
跑命令tool-bash 插件
搜索历史会话session_search(dsh-tool-session-query)
任务拆分给多 Agent子 Agent / 工作流定义
定时提醒/调度定时调度接口
接入外部工具 (MCP)MCP 集成插件
长期目标推进目标与待办管理系统

一切皆插件的哲学

1. 架构设计原则

DSH 采用 “一切皆插件” 的顶层设计：

官方原文：“它采用了『一切皆插件』的架构：新增能力 = 写插件(工具、服务、事件、UI)，修改行为 = 换插件 / 叠 patch 层,不改核心。核心只留一个 AgentLoop 具体循环：‘新行为应放入插件,而不是这里’。”

2. 插件类型分类

插件类型说明示例
工具插件提供具体的执行能力（文件、命令、网络等）tool-fs、tool-bash、session_search
服务插件提供持久化或外部服务集成MCP 集成、数据库连接、API 服务
事件插件处理异步事件和钩子Webhook 规则、定时任务触发
UI 面板插件扩展可视化界面工作台扩展、自定义视图

3. 行为修改机制

  • 换插件：直接替换对应的插件实现
  • 叠 patch 层：在 Profile 中通过 patch 机制叠加配置，而不修改核心代码
  • 配置覆盖：用户自定义配置优先于默认配置

const { createPlugin } = require('@deepseek-ai/cordis');

module.exports = createPlugin({
  name: 'my-custom-plugin',
  async onLoad(context) {
    // 注册自定义工具
    context.registerTool('my-tool', {
      description: '我的自定义工具',
      execute: async (args) => {
        // 实现具体逻辑
        return { result: 'success' };
      }
    });
  }
});

2. 插件开发要点

要点说明
Seam 注册在 onLoad 中通过 context.registerTool()、context.registerService() 注册能力
Context 获取通过 context.llm、context.tools、context.sandbox 等获取核心能力
Patch 机制通过 Profile 的 patch 层实现配置的叠加和自定义
版本兼容注意插件版本与 DSH/Core 版本的兼容性

3. 发布与分享插件

  • 将插件发布到 npm: npm publish
  • 或提交到 DeepSeek Harness 社区仓库
  • 配合 Profile 进行版本管理和分发

常见问题与排查

问题原因解决方案
Command not found: dsh未安装或未配置环境变量npm install -g @deepseek-ai/dsh 或检查 PATH
Web 界面启动失败（端口占用）3080 端口被占用修改配置：dsh web --port 3081 或杀占用进程
插件加载失败版本不兼容或 plugin.json 格式错误检查 DSH 版本，验证 plugin.json 结构
权限被拒绝缺少沙箱权限或配置错误检查 ~/.dsh/config.json 的权限设置
模型路由不生效缺少 Provider 配置在 --model_args 中指定模型提供者
任务卡死或超时循环未终止或工具执行错误检查任务是否有明确的结束条件

配置文件位置

  • ~/.dsh/config.json - 主配置文件
  • ~/.dsh/profiles/ - Profile 目录

最佳实践建议

  1. 先用 Web 工作台：熟悉 DSH 界面和基本操作后，再尝试 CLI 与插件开发。
  2. 使用 Profile 进行自定义：通过创建自定义 Profile，在不修改核心的情况下组合所需插件。
  3. 利用 Patch 机制：对于常用的微调，使用 patch 而非 Fork 核心代码。
  4. 关注社区生态：DeepSeek Harness 社区已有众多插件，优先检查现有插件是否满足需求。
  5. 配合 MCP 使用：MCP (Model-Controller-Protocol) 集成可显著扩展 DSH 的自动化能力。
  6. 保持插件轻量：插件应专注于单一职责，避免过于臃肿，便于维护和复用。
