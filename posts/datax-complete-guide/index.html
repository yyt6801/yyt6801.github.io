DataX 是阿里巴巴开源的离线数据同步工具，广泛应用于阿里内部各种异构数据源的离线同步场景，每天处理 TB 级别的数据。它支持关系型数据库（MySQL、Oracle、PostgreSQL、SQL Server）、NoSQL（MongoDB、Redis）、大数据平台（HDFS、Hive、MaxCompute、ClickHouse）等数十种数据源，是国内数据仓库和数据湖建设中常用的数据迁移与同步工具。

核心优势：

  • 开源免费：基于 Apache 2.0 协议，无商业授权限制
  • 异构支持：内置数十种 Reader/Writer 插件，支持主流数据库和大数据组件
  • 高性能：支持多通道并行同步、批量读写、流量控制
  • 运维友好：提供命令行运行、Web 监控（DataX-Web）、错误数据重试机制
  • 扩展性强：基于插件架构，可自定义 Reader/Writer

1. 下载与安装

从 DataX GitHub 仓库 下载最新稳定版，或通过源码编译。

任务 JSON 配置详解

一个标准的 DataX 作业 JSON 分为 job.setting 和 job.content 两部分。

job.setting —— 作业级配置

配置项说明默认值必填
speed.channel并行通道数（线程数）1否
speed.byte每秒最大字节数（流量控制）0（不限制）否
speed.record每秒最大记录数（流量控制）0（不限制）否
errorLimit.record最大允许脏数据记录数0（不允许）否
errorLimit.percentage最大允许脏数据占比（0~1）0.0否

示例：

"setting": {
  "speed": {
    "channel": 5,
    "byte": 52428800,
    "record": 100000

    "record": 1000,
    "percentage": 0.01
  }
}

job.content —— 数据内容配置

content 是一个数组，每个元素代表一个子任务，包含 reader 和 writer。

配置项说明
reader.nameReader 插件名称，如 mysqlreader、oraclereader
reader.parameterReader 连接与读取参数
writer.nameWriter 插件名称，如 clickhousewriter、hdfswriter
writer.parameterWriter 连接与写入参数

where附加过滤条件（与 querySql 二选一）
querySql自定义 SQL，适合复杂查询，与 table / where 互斥
connection.jdbcUrlJDBC 连接串

性能优化与调优

1. 并行度调优

优化项建议说明
speed.channel设置为 CPU 核数的 1~2 倍过高会增加数据库压力，过低浪费资源
MySQL splitPk必须指定有索引的主键或唯一列未指定时 DataX 会退化为单通道串行读取
ClickHouse batchSize2000~10000过小增加交互次数，过大增加内存占用

2. 流量控制

为避免同步任务占满生产数据库带宽，建议限制写入速率：

1
2
3
4
5

"speed": {
  "channel": 3,
  "byte": 10485760,
  "record": 20000
}

3. 错误数据处理

开启脏数据容错，避免单条异常数据导致整个任务失败：

1
2
3
4

"errorLimit": {
  "record": 1000,
  "percentage": 0.01
}

DataX 会将脏数据写入 tmp/ 目录下的错误文件，供后续人工核对和重试。

4. 字段类型映射注意事项

不同数据库的字段类型可能不完全对应，常见问题如下：

源数据库目标数据库常见问题解决方案
MySQL DATETIMEClickHouse DateTime时区不一致JDBC URL 添加 serverTimezone=UTC，ClickHouse 表使用 DateTime('UTC')
MySQL DECIMALClickHouse Decimal精度丢失确保目标表精度与源一致
Oracle NUMBERMySQL BIGINT溢出转换前评估数值范围，必要时拆分字段

离线环境部署与运维

在无法访问互联网的内网或离线环境中部署 DataX，需准备以下内容：

1. 离线安装包准备

在有网机器编译打包后，将整个 target/datax 目录拷贝到目标机器：

1
2
3
4
5
6

# 有网机器
mvn -U -X package -DskipTests
tar -czf datax-offline.tar.gz target/datax/

# 拷贝到离线机器并解压
tar -xzf datax-offline.tar.gz

2. 依赖 JAR 包离线放置

部分 Reader/Writer 依赖的第三方 JDBC 驱动不在默认 libs/ 中，需手动放置：

数据源驱动 JAR 示例放置目录
MySQLmysql-connector-java-8.0.x.jarplugin/mysqlreader/libs/
Oracleojdbc8.jarplugin/oraclereader/libs/
ClickHouseclickhouse-jdbc-x.x.x.jarplugin/clickhousewriter/libs/

3. 日志与监控

  • 运行日志：默认输出到控制台，可重定向到文件，或通过 -log 参数指定日志级别
  • DataX-Web：社区提供的 Web 管理界面，支持可视化配置任务、查看运行状态、重试脏数据，适合团队共用
  • 错误文件：脏数据写入 ${jobName}.error.log，位于 tmp/ 目录

4. 常见问题排查

现象可能原因解决方案
ClassNotFoundException缺少 JDBC 驱动 JAR将对应驱动放入插件 libs/ 目录，重启 DataX
Access denied for user数据库账号密码错误或权限不足核对账号密码，确认源库授权了远程连接
Communications link failure网络不通或防火墙拦截检查端口（3306/8123 等）、安全组、防火墙规则
任务运行极慢通道数过低或未指定 splitPk提高 channel，为 MySQL Reader 指定有索引的 splitPk
脏数据过多字段类型不匹配或数据非法检查源表与目标表的字段类型映射，清洗源数据

最佳实践建议

  1. 全量与增量分离：全量同步使用 table + where 时间范围；增量同步建议使用 querySql 结合水位字段（如 update_time > last_sync_time）。
  2. 生产环境限流：同步生产库时务必设置 speed.byte 或 speed.record，避免影响在线业务。
  3. 目标表预处理：ClickHouse 等列式存储建议在 preSql 中执行分区清理，避免重复数据。
  4. 任务拆分：大表建议按时间或主键范围拆分为多个 DataX 任务并行执行，降低单任务风险。
  5. 配置版本化：将所有任务 JSON 文件纳入 Git 版本管理，便于回滚和审计。
  6. 敏感信息脱敏：生产环境中数据库密码建议通过环境变量或加密配置注入，避免明文写在 JSON 中。
